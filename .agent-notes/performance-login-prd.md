# PRD: 모바일 체감 성능 및 로그인 지연 개선

## Problem Statement

사용자는 사이트 접속 직후 홈 화면부터 버벅임을 느끼고, 지도 화면에서는 더 심한 지연을 경험한다. 특히 모바일 환경에서 화면 전환, 초기 렌더링, 지도 조작, 로그인 후 사용자 상태 반영이 늦게 느껴진다.

현재 확인된 원인은 하나의 단일 버그라기보다, 전역 지도 SDK 로드, 홈 전체 클라이언트 렌더링, 과한 애니메이션/블러 효과, 지도 마커 전체 재생성, 로그인 후 중복 사용자 조회가 겹친 구조적 성능 문제다.

## Solution

홈과 지도 화면의 초기 렌더링 비용을 줄이고, 모바일에서 지속적으로 실행되는 애니메이션과 고비용 시각 효과를 제한한다. 지도 SDK는 지도 화면에서만 로드하고, 홈은 서버 컴포넌트 중심으로 재구성한다. 로그인 흐름은 성공 직후 이미 확보한 사용자 정보를 최대한 활용해 중복 API/DB 조회를 줄인다.

목표는 디자인 방향을 유지하면서 모바일에서 첫 화면 표시, 스크롤, 지도 조작, 로그인 반영 속도를 개선하는 것이다.

## User Stories

1. 모바일 사용자는 홈 화면에 접속했을 때 첫 화면이 빠르게 표시되기를 원한다. 그래야 앱이 멈춘 것처럼 느끼지 않는다.
2. 모바일 사용자는 홈 화면 스크롤이 부드럽기를 원한다. 그래야 주요 기능으로 자연스럽게 이동할 수 있다.
3. 모바일 사용자는 지도 화면에 진입했을 때 마커와 지도 조작이 끊기지 않기를 원한다. 그래야 주변 카페를 쉽게 탐색할 수 있다.
4. 모바일 사용자는 카페 필터를 바꿨을 때 화면이 갑자기 멈추지 않기를 원한다. 그래야 조건을 바꿔가며 탐색할 수 있다.
5. 모바일 사용자는 카페 마커를 눌렀을 때 선택 상태가 빠르게 반영되기를 원한다. 그래야 지도 탐색 흐름이 끊기지 않는다.
6. 사용자는 홈에서 지도 기능을 쓰지 않을 때 지도 SDK 로딩 비용을 내지 않기를 원한다. 그래야 홈이 가볍게 열린다.
7. 사용자는 로그인 버튼을 누른 뒤 로그인 완료 상태가 빠르게 반영되기를 원한다. 그래야 로그인 성공 여부를 혼동하지 않는다.
8. 사용자는 로그인 후 원래 보던 페이지로 자연스럽게 돌아오기를 원한다. 그래야 탐색 흐름이 끊기지 않는다.
9. 로그인 사용자는 프로필과 저장 목록이 늦게 갱신되더라도 화면이 멈추지 않기를 원한다. 그래야 앱을 계속 사용할 수 있다.
10. 운영자는 성능 개선 후에도 기존 카페 탐색, 즐겨찾기, 로그인, 관리자 진입 기능이 깨지지 않기를 원한다.

## Implementation Decisions

- 지도 SDK는 전역 레이아웃에서 로드하지 않고, 지도 화면 또는 지도 컴포넌트가 필요한 시점에만 로드한다.
- 홈 화면은 가능한 서버 컴포넌트 중심으로 두고, 사용자 상태, 로그인 버튼, 프로필 편집처럼 브라우저 상태가 필요한 부분만 클라이언트 컴포넌트로 분리한다.
- 홈의 무한 애니메이션, 큰 blur, 큰 shadow, 복잡한 radial gradient는 모바일에서 축소하거나 정적 표현으로 대체한다.
- 프로필 편집 시트처럼 초기 화면에 필요 없는 무거운 UI는 열릴 때 로드하는 방식으로 분리한다.
- 지도 마커는 필터나 선택 변경 때마다 전체 삭제 후 재생성하지 않고, 가능한 기존 overlay를 재사용한다.
- 모바일 지도에서는 모든 마커의 증기 애니메이션을 기본 비활성화하거나, 선택된 마커에만 제한한다.
- 지도 화면의 글래스모피즘 blur는 모바일에서 강도를 낮추거나 배경색 기반 표현으로 대체한다.
- 로그인 callback에서 이미 확보한 사용자 정보를 활용해 로그인 직후 사용자 상태 반영을 빠르게 만든다.
- 로그인 성공 후 클라이언트가 즉시 다시 사용자 조회를 수행하는 중복 흐름을 줄인다.
- 기존 유저 로그인 시 사용자 정보 갱신 로직은 불필요한 DB 왕복을 줄인다.
- 데이터 캐싱은 최신성이 꼭 필요한 인증 정보와 정적 카페 데이터를 구분해서 적용한다.

## Testing Decisions

- 테스트는 구현 내부가 아니라 사용자 입장에서 보이는 외부 동작을 기준으로 작성한다.
- 로그인 흐름 테스트는 인증 쿠키가 있을 때 사용자 정보가 정상 반환되는지, 인증 쿠키가 없을 때 null 사용자로 처리되는지 검증한다.
- 사용자 상태 훅은 로컬 익명 사용자, 인증 사용자 동기화, 로그아웃 후 익명 사용자 복귀를 검증한다.
- 지도 마커 최적화는 필터 변경 후 표시되는 카페 수와 선택 동작이 유지되는지 중심으로 검증한다.
- 홈 분리 작업은 주요 링크, 로그인 버튼, 프로필 버튼, 원두 카드 진입 동작이 유지되는지 검증한다.
- 성능 개선 작업 후 타입 검사, 린트, 빌드를 실행한다.
- 가능하면 모바일 viewport에서 홈과 지도 화면을 수동 QA한다.

## Out of Scope

- 전체 UI/UX 리디자인
- 새로운 지도 라이브러리 도입
- 새 인증 라이브러리 도입
- 데이터베이스 스키마 대규모 변경
- 카페 데이터 운영 정책 변경
- 원두/CBTI 기능 개편
- 관리자 기능 개편

## Further Notes

- 현재 문제는 단일 병목으로 단정하기 어렵다. 코드 기준으로는 홈의 전역 SDK 로드와 전체 클라이언트 렌더링, 지도 화면의 마커 애니메이션과 overlay 재생성이 우선 개선 대상이다.
- 실제 개선 효과는 모바일 기기 또는 모바일 viewport에서 측정해야 한다.
- 구현은 한 번에 대규모로 바꾸기보다, 전역 SDK 제거와 홈 클라이언트 범위 축소부터 작은 단위로 진행하는 것이 안전하다.
