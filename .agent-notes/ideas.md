# coFFFFFe-map 아이디어 목록

## 목적

- 이벤트 아이디어와 서비스 고유 기능 후보를 한곳에 모은다.
- 바로 구현하지 않고, 우선순위와 구현 가능성을 검토한 뒤 GitHub issue로 분리한다.
- 현재 서비스의 핵심인 안산 카페 탐색, 지도, 원두 정보, 취향 추천과 연결되는 아이디어를 우선한다.

## 이벤트 아이디어

### 1. 모르겠으면 랜덤 카페 추천

- 목적: 사용자가 선택 피로 없이 바로 갈 카페를 정하게 한다.
- 핵심 경험:
  - 내 주변 카페 중 랜덤 추천
  - 도보 / 드라이브 모드 선택
  - 카페 나들이 경로 추천
- 확장 가능성:
  - Kakao 지도 길찾기 연계
  - 외부 지도 서비스 연계
  - 날씨, 시간대, 이동 수단 기반 추천
- 기대 효과:
  - 사용자가 서비스를 다시 열 이유를 만든다.
  - 다른 서비스와 연계할 가능성을 높인다.
- 우선순위: 높음
- 구현 난이도: 중간
- issue화 후보: 예

### 2. 원두 취향 투표

- 목적: 사용자가 원두 취향을 가볍게 표현하고, 다른 사람의 선호도도 확인하게 한다.
- 핵심 경험:
  - 이번 주 원두 취향 투표
  - 이번 주 1등 원두 공개
  - 1등 원두 취급 카페 보여주기
- 확장 가능성:
  - 주간 랭킹
  - 원두별 취급점 연결
  - 사용자 취향 데이터 축적
  - 시즌 이벤트와 연결
- 기대 효과:
  - 원두 데이터를 단순 정보가 아니라 참여형 콘텐츠로 만든다.
  - 카페 상세 페이지와 원두 페이지의 연결성을 높인다.
- 우선순위: 중간
- 구현 난이도: 중간
- issue화 후보: 보류

## 내 서비스만의 기능

### 1. CBTI 기반 카페 추천

- 메모: `CBTI`라는 이름은 변경을 검토한다.
- 목적: 사용자의 커피 취향을 카페 추천으로 자연스럽게 연결한다.
- 핵심 경험:
  - 커피 취향 테스트 진행
  - 결과 타입 제공
  - 결과에 맞는 카페 / 원두 추천
- 이름 후보:
  - 커피 취향 테스트
  - 원두 취향 테스트
  - 내 커피 타입
  - 커피 성향 찾기
  - 오늘의 커피 성향
- 기대 효과:
  - 단순 테스트에서 끝나지 않고 실제 카페 탐색으로 이어진다.
  - coFFFFFe-map만의 추천 경험을 만들 수 있다.
- 우선순위: 높음
- 구현 난이도: 중간
- issue화 후보: 예

### 2. 저 다녀갔어요 기능

- 목적: 사용자가 방문 기록을 가볍게 남기게 한다.
- 핵심 경험:
  - 카페 상세에서 "저 다녀갔어요" 표시
  - 카페별 방문 수 표시
  - 내가 다녀간 카페 모아보기
- 확장 가능성:
  - 방문 기록 기반 추천
  - 원두 뱃지 컬렉션과 연결
  - 한줄평 작성 흐름과 연결
- 기대 효과:
  - 회원가입 부담이 크지 않은 참여 기능을 만들 수 있다.
  - 카페 상세 페이지에 살아있는 반응을 추가한다.
- 우선순위: 높음
- 구현 난이도: 중간
- issue화 후보: 예

### 3. 랜덤닉 한줄평 / 이모티콘 후기

- 목적: 사용자가 긴 리뷰 대신 짧고 부담 없는 반응을 남기게 한다.
- 핵심 경험:
  - 랜덤 닉네임 자동 생성
  - 한줄평 작성
  - 이모티콘 또는 감정 태그 선택
- 표현 예시:
  - `산미요정123: 조용해서 작업하기 좋았어요`
  - `고소함`
  - `조용함`
  - `주차 편함`
- 확장 가능성:
  - 카페 분위기 태그 자동 집계
  - 카페 상세의 빠른 후기 영역
  - "저 다녀갔어요" 이후 후속 입력
- 기대 효과:
  - 리뷰 작성 부담을 줄인다.
  - 카페의 분위기를 빠르게 파악할 수 있게 한다.
- 우선순위: 중간
- 구현 난이도: 중간
- issue화 후보: 보류

### 4. 원두 뱃지 컬렉션

- 목적: 사용자가 원두 탐색을 수집형 경험으로 느끼게 한다.
- 핵심 경험:
  - 특정 원두를 마시면 뱃지 획득
  - 산미 / 고소함 / 디카페인 / 싱글오리진 등 뱃지 분류
  - 내 컬렉션 페이지 제공
- 확장 가능성:
  - 방문 기록과 연결
  - 원두 취향 테스트 결과와 연결
  - 시즌 이벤트와 연결
- 기대 효과:
  - 원두 탐색을 반복 방문 동기로 바꿀 수 있다.
  - 서비스만의 게임적 요소를 만들 수 있다.
- 우선순위: 낮음
- 구현 난이도: 높음
- issue화 후보: 나중

## issue로 만들기 전 확인할 것

- 사용자가 어느 화면에서 시작하는가?
- 저장이 필요한 데이터가 있는가?
- 로그인 없이 가능한가, 로그인이 필요한가?
- 현재 정적 데이터만으로 가능한가?
- 완료 조건을 2~5개로 적을 수 있는가?
